# Промпт для LLM — Lab2

LLM: Claude (Claude Code, модель Claude Opus 5.5).
Исходный код — бот из Lab1 ([../lab1/bot.py](../lab1/bot.py)), передаётся LLM вместе с промптом.

## Версия 1 (исходный промпт)

```text
Улучши моего Telegram-бота (код bot.py прилагается): добавь приём голосовых сообщений
и интеграцию с двумя внешними API — OpenAI и Google Calendar.

ТЕКУЩИЙ ФУНКЦИОНАЛ БОТА:
- любое текстовое сообщение сохраняется как задача (SQLite), «!» в начале — высокий приоритет;
- приоритеты 🔴/🟡/🟢, смена inline-кнопками;
- /list, /done <N>, /delete <N> — список дел и работа с ним;
- /remind <30m|2h|18:30> <текст>, /reminders — напоминания через JobQueue,
  переживают перезапуск;
- /note <текст>, /notes — заметки;
- часовой пояс из .env (TIMEZONE).

НОВЫЙ ФУНКЦИОНАЛ:
1. Голосовые сообщения. Бот принимает голосовое, скачивает его и распознаёт речь через
   OpenAI Audio API (модель из .env, по умолчанию gpt-4o-mini-transcribe).
   Пользователю сначала показывается распознанный текст: «🎙 Распознал: …».
2. Понимание намерения. Распознанный текст отправляется в OpenAI Chat Completions
   (модель из .env, по умолчанию gpt-4o-mini) с JSON-ответом (response_format = json_object).
   В системный промпт передаются текущие дата, время и часовой пояс пользователя, чтобы
   модель превращала «завтра в 10», «в пятницу вечером» в точную дату и время.
   Модель выбирает одно действие:
   - "event" — событие в календаре: title, start (ISO 8601 с часовым поясом),
     duration_minutes (по умолчанию 60);
   - "note" — заметка: text;
   - "task" — задача: text, priority (1 — высокий, 2 — средний, 3 — низкий).
   Если не понятно, что хочет пользователь, — сохранить как задачу.
3. Google Calendar. Для "event" бот создаёт событие в Google Calendar и отвечает:
   «📅 Добавил в календарь: <название>, <дата и время>» + ссылка на событие.
   Для "note" и "task" используются уже существующие функции сохранения в SQLite.
4. Новая команда /events — 5 ближайших событий из Google Calendar:
   «📅 Ближайшие события:» и строки «• 17.10 10:00 — Встреча с командой».

ДАННЫЕ:
- OpenAI API: https://platform.openai.com/docs/api-reference/audio
  и https://platform.openai.com/docs/api-reference/chat, библиотека openai.
- Google Calendar API v3: https://developers.google.com/calendar/api/v3/reference/events
  (events.insert, events.list), библиотеки google-api-python-client и google-auth.
- Авторизация Google через сервисный аккаунт: JSON-ключ в файле credentials.json,
  календарь пользователя расшарен на email сервисного аккаунта.
- Новые переменные .env: OPENAI_API_KEY, OPENAI_MODEL, OPENAI_STT_MODEL,
  GOOGLE_CREDENTIALS_FILE (по умолчанию credentials.json), GOOGLE_CALENDAR_ID.
- Таблицы SQLite не меняются.

ТРЕБОВАНИЯ:
- Весь существующий функционал сохраняется без изменений (текстовые сообщения по-прежнему
  сразу становятся задачами, без OpenAI).
- Код простой и понятный, по-прежнему один файл bot.py, комментарии на русском.
- Синхронные вызовы Google API и OpenAI не должны блокировать бота
  (использовать AsyncOpenAI и asyncio.to_thread для Google).
- Обработка ошибок, у каждой — понятное сообщение пользователю:
  не задан OPENAI_API_KEY или нет credentials.json (бот запускается, голос/календарь
  отвечают «интеграция не настроена»), пустое распознавание, невалидный JSON от модели,
  ошибки сети и API (Google HttpError, openai.APIError).
- Пока идёт обработка голосового, показывать статус «печатает…» (ChatAction.TYPING).
- Логирование распознанного текста и выбранного действия.

СОЗДАЙ:
1. Обновлённый bot.py
2. Обновлённые requirements.txt и .env.example
3. Обновлённый README.md с инструкцией по настройке OpenAI и Google Calendar
```

## Итерации

### Итерация 1 — первый запуск

Код по промпту v1 заработал с первого раза: голосовые распознаются, события создаются
в Google Calendar, заметки и задачи — в SQLite. Перед запуском обе интеграции проверены
отдельным скриптом (список событий календаря + тестовый разбор фразы через OpenAI).

### Итерация 2 — ошибки, найденные на демо

**Проблемы** (видно в видео-демо и на скриншоте `06_show_notes_bug.png`):
1. «Можешь показать, какие у меня заметки?» → бот сохранил **задачу** «Показать существующие заметки».
2. «Поставь на завтра на 2 часа время для фокуса…» → событие на 09:00 длительностью **60 мин** вместо 120.
3. Под каждой ссылкой на событие Telegram показывает большую рекламную карточку «Google Workspace».

**Промпт:**

```text
По итогам тестирования три проблемы:
1. Голосовое «Можешь показать, какие у меня заметки?» сохранилось как задача
   «Показать существующие заметки». Добавь действие "show" с полем what
   (tasks | notes | events): бот должен выполнить то же, что команды /list, /notes, /events.
2. «Поставь на завтра на 2 часа время для фокуса» создало событие на 60 минут.
   Уточни правила в системном промпте: «на 2 часа», «часик», «на полтора часа» без «в»
   перед числом — это длительность, а не время начала. При этом «встреча на 14 часов»
   по-прежнему означает начало в 14:00.
3. Под ссылкой на событие Telegram рисует большое превью Google Workspace — отключи его.
```

**Результат:** проверка на реальном OpenAI — все фразы из демо разобраны верно,
регрессий нет:

| Фраза | Было | Стало |
|---|---|---|
| «Можешь показать, какие у меня заметки?» | `task` | `show` → `notes` |
| «Что у меня в календаре на ближайшее время?» | — | `show` → `events` |
| «…на завтра на 2 часа часик времени для фокуса…» | `event`, 60 мин | `event`, **120 мин** |
| «…встречу на 14 часов с друзьями…» | `event` 14:00 | `event` 14:00 (без изменений) |
| «…в 16 часов с друзьями на полтора часа» | `event` 16:00, 90 мин | без изменений |
| «Запиши в заметку… плавки и крем SPF» | `note` | без изменений |
| «Надо срочно купить подарок маме» | `task`, 🔴 | без изменений |
