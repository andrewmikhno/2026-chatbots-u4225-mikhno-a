## Версия 1 — подготовка к деплою для реальных пользователей

```text
Подготовь моего Telegram-бота (bot.py из Lab2 прилагается) к деплою на собственный VPS
в Docker и к тестированию реальными пользователями (3–5 человек).

ТЕКУЩИЙ ФУНКЦИОНАЛ:
- задачи с приоритетами, /list, /done, /delete; напоминания /remind (JobQueue);
  заметки /note, /notes — всё в SQLite;
- голосовые: распознавание через OpenAI → JSON-намерение event / note / task / show;
- события в Google Calendar через сервисный аккаунт, /events.

ПРОБЛЕМА:
Google Calendar — мой личный. Если бота откроют другие люди, их голосовые события
попадут в мой календарь, а /events покажет им мои события.

ЧТО НУЖНО:
1. Владелец бота: переменная OWNER_ID в .env (мой Telegram user id).
   - Google Calendar (создание событий голосом и /events) доступен только владельцу.
   - Остальным пользователям: голосовое-событие сохраняется как задача с пояснением
     «📅 Календарь доступен только владельцу бота, сохранил как задачу»;
     /events отвечает тем же пояснением.
   - Всё остальное (задачи, заметки, напоминания, голосовые → заметки/задачи) доступно всем,
     данные изолированы по user_id, как и раньше.
2. Статистика использования для отчёта:
   - таблица usage (id, user_id, action, created_at), куда пишется каждое действие:
     text_task, voice_event, voice_note, voice_task, voice_show, remind, note, done;
   - команда /stats — только для владельца: число уникальных пользователей,
     действий всего и по типам, задач/заметок/напоминаний в БД, активность за последние 24 часа.
3. Docker:
   - Dockerfile: python:3.12-slim, рабочая папка /app, установка зависимостей
     pip --no-cache-dir, копирование bot.py, запуск python bot.py, PYTHONUNBUFFERED=1.
   - .dockerignore: .env, credentials.json, *.db, .venv, __pycache__, screenshots, demo.
   - docker-compose.yml: сервис bot, сборка из текущей папки, env_file .env,
     restart: unless-stopped; база в именованном volume (DB_PATH=/app/data/bot.db);
     credentials.json монтируется только для чтения; ротация логов json-file
     (max-size 10m, max-file 3), чтобы логи не съели диск.
4. Бот работает через long polling — входящие порты и webhook не нужны.

ТРЕБОВАНИЯ:
- Весь существующий функционал сохраняется.
- Секреты (.env, credentials.json) не попадают ни в Git, ни в Docker-образ.
- Код по-прежнему в одном файле bot.py, комментарии на русском.
- Логирование: время, уровень, логгер, сообщение; уровень INFO.

СОЗДАЙ:
1. Обновлённый bot.py
2. Dockerfile, .dockerignore, docker-compose.yml
3. Обновлённые .env.example и README.md с инструкцией деплоя на VPS
```
